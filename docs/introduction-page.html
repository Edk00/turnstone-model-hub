Turnstone Model Hub

Self-hosted model management for Turnstone. Find the open models worth running, see what your hardware can hold and how fast it will go, download them safely, and hand them to Turnstone as ready-to-use endpoints, all from one local dashboard.

license Apache-2.0 python 3.11+ dependencies stdlib only works with Turnstone 1.8 platform Windows + WSL 2

Turnstone is named after a shorebird that flips stones to see what's underneath. Model Hub does the same for the model landscape: what's new, what's popular and what actually fits, before you spend 80 GB of bandwidth finding out.

Standalone and unofficial. Model Hub is an independent project. It is not part of, affiliated with, or endorsed by Turnstone Labs, who create and maintain Turnstone; all credit for the original system goes to them. Model Hub talks to Turnstone only through the console's public admin API. Anyone is welcome to try it and leave feedback below.

What it does

Everything on the model side of Turnstone

Knows your hardware

Detects the GPU on any vendor, unified vs. dedicated memory, live GPU memory use, RAM bandwidth and the memory left for models. Every value shows whether it was detected, derived or assumed.

Plans unified memory

On unified-memory APUs (e.g. AMD Ryzen AI Max), shows how the BIOS splits RAM between CPU and GPU and what another split would let you run. Greyed out on GPUs with their own VRAM.

Fit and speed before you download

Every GGUF variant with memory needed for your context, a fit verdict, tokens per second and seconds per Turnstone agent turn. One benchmark calibrates the estimates to your machine.

What to run next

Newer releases in the families you use, a watchlist (DeepSeek, Kimi, GLM, MiniMax, Qwen, Gemma, Nemotron, gpt-oss) and what's trending on Hugging Face and GitHub.

Safe downloads

Hugging Face, ModelScope and GitHub releases. Weights-only formats, allow-listed HTTPS hosts and mandatory SHA-256 checks. Pickle files and executables are refused.

One-step hand-off to Turnstone

Starts the llama.cpp server, confirms a Turnstone node can reach it, registers it in the Models tab, and fixes the endpoints when Windows changes the WSL address.

How it fits

Turnstone calls the models; Model Hub keeps them ready

Turnstone never reads model files. Its nodes call each model's llama.cpp server over HTTP. Model Hub makes sure those servers exist, are reachable from Turnstone's containers, and are registered correctly.

Hardware support

Unified memory gets the planner; everything gets the estimates

GPU typeMemory model used for fitRAM split planner
Unified memoryBIOS-reserved GPU memory + Windows RAM the GPU may borrow (AMD Ryzen AI / Strix Halo, other APUs, Intel iGPUs)active
Dedicated VRAMVRAM; overflow modelled as partial CPU offload (NVIDIA, AMD Radeon RX / PRO)greyed out
No GPUSystem RAM, CPU inferencegreyed out

RAM figures on unified memory are indicative. CPU and GPU share one pool, and Windows counts it in overlapping buckets that miss some driver allocations, so RAM used/available, GPU memory, the split and “fit” may not be correct. The dashboard shows this note in the Hardware detection panel; check Task Manager and benchmark before relying on them.

Test system: one unified-memory mini PC (AMD Ryzen AI Max+ 395, 128 GB) with llama.cpp Vulkan. Discrete-GPU and CPU-only configurations are covered by unit tests only.

Prior art

Similar projects on GitHub

Several open-source tools already cover parts of this. None of the ones found targets Turnstone, so the Turnstone hand-off, the Windows + WSL unified-memory planner and per-agent-turn estimates are what Model Hub adds. The fit and speed maths overlaps heavily with llmfit, which is far more mature; reusing it or gguf-parser is an open question below.

Try it

Run it next to Turnstone

cd model-hub
.\run-hub.ps1                 # opens http://127.0.0.1:8099
.\run-hub.ps1 -Background     # or run hidden; stop with .\stop-hub.ps1

Needs Python 3.11+, llama.cpp's llama-server, and Turnstone 1.8+ in WSL 2 for model registration. Discovery, estimates and downloads work without Turnstone.
